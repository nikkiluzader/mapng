How MapNG is built

MapNG's code is written with Claude, an AI model made by Anthropic. I direct it, review it and test it. This page says what each of us does, how every change is checked, and where the checks fall short.

Who does what

I'm Nikki. I started MapNG in November 2025 and it has had over a thousand changes since. I don't type most of the code any more; Claude does. That is not the same as asking for an app and shipping whatever comes back.

What I do

  • Decide what MapNG should do, and what it should not.
  • Choose the data sources, and read their licences and usage rules.
  • Set the rules the code must follow (some are listed below).
  • Read tester reports and decide what to fix first.
  • Look at the result in the game and say when it is wrong.
  • Decide what goes to the public site and what stays a test build.

What Claude does

  • Writes the code and its tests.
  • Finds the cause of a reported bug and shows the evidence.
  • Runs the test suite, the export sweep and the in-game checks.
  • Makes the plots and before and after pictures I review.
  • Says what it did not verify, so I know what is still a guess.

How a change is tested

  1. Automated tests. About 1,100 tests in 167 files cover the pieces: road widths, bridges and tunnels, water, terrain repair, map data reading, the texts in all seven languages, and more. A change is kept only when all of them pass.
  2. A plot first. For anything that shapes terrain or structures, the expected result is drawn from above before a level is exported, so a wrong idea is caught before it is built.
  3. The export sweep. Before a change reaches the public site, MapNG exports 99 complete levels: a set of real test places, each on three elevation sources (1 m lidar, free lidar, global 30 m) and three terrain settings. Each export is measured (road steps, steep spots, sidewalks floating or buried, bridge decks, tunnels) and compared with recorded results. A number that got worse stops the change.
  4. In the game. Levels are loaded in BeamNG.drive and checked from several angles and from the driver's seat. Where it can be measured, it is: rays cast onto the road surface, heights read every half metre through a tunnel.
  5. Test builds, then releases. Desktop test builds go to testers who opted in. The stable release and the public site get a change only after that, and only when I say so.

Rules the code has to follow

These are mine, and some of them are enforced by tests.

  • No special cases for places. A fix has to be a general rule that works everywhere. A test fails if a place name appears in the code.
  • Open data only, worldwide where possible, and within each source's usage policy. OpenStreetMap's servers are asked as little as possible; MapNG keeps its own copy of the map for that reason.
  • Nothing is sent without your choice. What can be sent, and when, is on the data page, and a test checks that the page's example matches what the app really sends.
  • Exporting never downloads. Everything is fetched when you generate, so an export cannot fail halfway on a network error.
  • Every text in seven languages, checked by a test.

One day, as an example

13 November 2026. Two reports came in from testers, and both were fixed the same day.

A map that used the wrong data

A tester near Naples saw his map fall back to a second-choice data source. The cause was a rounding mismatch of seven hundred-millionths of a degree along the edges where MapNG's map archives meet: a strip about 3.7 km deep was judged "not covered". It was fixed on the server for everyone, with no app update needed, and a test now covers it.

Roads under the ground

An experimental option builds BeamNG's Hero Roads over MapNG's roads. It went out in a test build after being tried only on flat ground. Within the hour a BeamNG developer reported that on hills most of the roads were under the terrain. He was right: measured in the game, terrain covered the road at 68% of the sampled points. After the fix it was 0.3%.

What the tests do not catch

Tests find what they were written to look for. They did not catch the roads under the ground above; a tester did. That is why new features are marked experimental, why test builds exist, and why reports matter.

  • The sweep uses a fixed set of places. The world has more shapes than that.
  • Looks are judged by eye. A level can pass every measurement and still look wrong.
  • Graphics cards and browsers differ. A problem report now includes the graphics card and driver for that reason.
  • Mistakes get through. When one does, the update notes say what happened and what changed.
