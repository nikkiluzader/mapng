What the hotspot map is

The 2D map in MapNG has an optional Export hotspots overlay, in the Map layers box. It shows the areas where people export BeamNG levels: a soft glow when you're zoomed out, brighter where more people export, and small dots once you zoom in. Everything on it comes only from people who chose to share. It helps everyone see where the community is building, and helps the developer decide where to improve MapNG next.

Sharing is off by default, on the website and in the desktop app. MapNG asks you once, after your first export, and the desktop app has an unticked box on its welcome screen. You can change your answer at any time with Share my exports (anonymous) in the Map layers box on the map.

Exactly what one report looks like

When sharing is on and a level export finishes, MapNG sends one small message to https://mapng.com/api/hotspots. This is its entire content:

POST /api/hotspots
Content-Type: application/json

{ "y": 2397, "x": 1973, "platform": "web" }
FieldWhat it is
yThe row of the ~5 km grid square your export's centre falls in. The world is divided into 0.05° squares: 3,600 rows from south to north.
xThe column of that square: 7,200 columns from west to east.
platform"web" or "desktop": which version of MapNG made the export.

Your browser or the desktop app converts your export's location into that square before sending, so the exact coordinates never leave your computer. A square is about 5.5 km tall, and narrower further from the equator. Row 2397, column 1973 above is the square that contains part of St. Augustine, Florida: every export anywhere inside it sends the same three values.

That is the whole report: no level name, no settings, no map data, no account, no device or browser ID, no cookies.

Exactly what is stored

For the hotspot map, the server keeps one table with one row per grid square that has had at least one shared export. Nothing else about hotspots is written anywhere. (Settings stats, if you opt in to those, are a separate table of totals: see below.)

ColumnTypeExampleMeaning
ywhole number2397Grid row of the square
xwhole number1973Grid column of the square
webwhole number14How many shared exports from the website fell in this square
desktopwhole number5How many shared exports from the desktop app fell in this square
last_daydate2026-11-04The day of the most recent one (a date, no time)

A report adds 1 to web or desktop for its square and sets last_day to today. Nothing records who sent it, and once added, a count cannot be traced back to anyone.

See all of it yourself

The full table is public. mapng.com/api/hotspots returns every row exactly as stored, with no filtering. It is the same data the overlay draws, refreshed at most 10 minutes behind the database.

To turn a row into a place: the square's centre is at latitude -90 + (y + 0.5) × 0.05 and longitude -180 + (x + 0.5) × 0.05.

The whole pipeline, step by step

  1. An export finishesyour computer
    Only BeamNG level exports count. Nothing happens unless sharing is on.
  2. MapNG works out the grid squareyour computer
    The centre of your export is rounded down to its 0.05° square (services/exportHotspots.js). The exact point is discarded.
  3. One report is sentnetwork
    The three values above go to mapng.com/api/hotspots over HTTPS. If you're offline, the report is simply dropped; it is never queued or retried.
  4. MapNG's Cloudflare Worker checks itCloudflare
    The Worker (worker/index.js) refuses anything that isn't a valid square and platform. To stop one machine spamming the map, it allows at most 30 reports per hour per address (details below). Request logging is switched off for this Worker.
  5. The count goes up by oneCloudflare Durable Object
    A single Durable Object (worker/hotspots.js) holds the table in its built-in SQLite storage and adds 1 to that square's row.
  6. The overlay reads the totalsnetwork
    Anyone who turns on the overlay downloads the table from /api/hotspots. Cloudflare keeps a copy for up to 10 minutes so the database isn't asked on every page view.
  7. The glow and dots are drawnyour computer
    Your browser draws the glow from the squares (services/heatLayer.js) and, zoomed in, merges nearby squares into one dot per group (services/hotspotLayer.js). Hovering or clicking only reads this same table.

The one thing kept in memory: spam protection

Without a limit, one person could fake thousands of exports. So for a short while the server remembers how many reports each address has sent this hour. It never writes this down. It works like this:

  • Your IP address is mixed with a fixed label and run through SHA-256, a one-way scramble. Only the first 8 bytes of the result are kept, in memory.
  • Next to it, a counter for the current hour. Over 30 reports in an hour, further reports are refused until the hour changes.
  • Entries from earlier hours are thrown away, and everything is lost whenever the server restarts. None of it is ever saved to storage or to a log.

Like every request to mapng.com, reports travel through Cloudflare's network, which runs the site. Cloudflare's own handling of traffic is covered by Cloudflare's privacy policy.

How the developer uses it

Only to look at the same totals everyone can see: which areas people build in. For example, MapNG hosts its own fast copy of OpenStreetMap data for a few regions, and the hotspot map shows which regions deserve that next. That's it.

Things MapNG will never do with it

  • Sell it
  • Share it with anyone (beyond the public totals on this page)
  • Use it for advertising
  • Track you, or link it to you
  • Combine it with any other data about you
  • Collect more without updating this page first

Your controls

  • Turn it on or off: the Map layers box on the map → Share my exports (anonymous). Turning it off stops reports immediately.
  • Where your choice lives: on your own computer only, in local storage under the key mapng_share_exports (on or off). Clearing your browser's site data resets it, and MapNG will ask again.
  • Check it yourself: open your browser's developer tools, go to the Network tab, and export a level. With sharing on you'll see one POST to /api/hotspots with the three values; with it off, you'll see none.
  • Removing past counts: because nothing links a count to a person, individual exports can't be found and removed. If the hotspot feature is ever retired, the table will be deleted.

Settings stats: which settings people use

A separate opt-in from the hotspot map, with its own switch (Share which settings I use in the Map layers box, asked once after your first export). It tells the developer which settings people really pick, so defaults can be better and settings nobody uses can go.

When it's on and a level export finishes, MapNG sends one message to https://mapng.com/api/usage. A typical one, in full:

POST /api/usage
Content-Type: application/json

{ "settings": { "platform": "desktop", "elevationSource": "default", "resolution": "4096",
  "metersPerPixel": "1", "mapData": "on", "overtureBuildings": "on", "advancedMode": "off",
  "rawTerrain": "off", "seaLevelOffset": "zero", "baseTexture": "game", "groundMaterials": "osm",
  "roads": "decal", "buildings": "on", "water": "on", "trees": "on", "forestDensity": "normal", "rocks": "on", "safeCaps": "on",
  "bridges": "on", "tunnels": "on", "measuredBridgeHeights": "on", "terrainEdits": "all", "shapeTerrain": "on",
  "shapeRoads": "on", "shapeBridges": "on", "shapeOverpasses": "on", "shapeTunnels": "on",
  "shapeExtras": "on", "shapeDetail": "on", "backdrop": "off" } }
  • Only fixed choices. Every value comes from a short fixed list (on/off, a texture name, a size), and the server refuses anything else. Sizes are rounded into groups. There is no free text, so nothing personal can slip in.
  • No location, ever. No coordinates, no grid square, no level name. It can't be matched to the hotspot map: the two are sent separately and neither carries anything that links them.
  • Only totals are stored. The server adds 1 to each setting's count ("Game Texture: 412") and keeps nothing per export. Your internet address is used only for spam protection (at most 30 an hour), in memory, as a one-way hash.

Problem reports from the desktop app

This is separate from the hotspot map. When the desktop app crashes, or an export, terrain generation or update fails, it can offer to send a problem report so the developer can fix it. You can also send one from Help → Report a Problem, or for one level from Send report in the levels list.

  • Nothing is sent unless you choose Send. There is no automatic sending. If you choose Don't send after a crash, you're not asked about that crash again.
  • You see what's included first. The report window lists everything in it and shows the end of the log it would send.
  • What a report can hold: the MapNG version, your operating system, how much memory and how many CPU threads you have, the error message, the job's log, the export settings, your control-panel settings as a session code, what you write, and the map's location and size (you can untick the location; the session code goes with it, since it includes the location). After a crash it also holds a crash snapshot (a "minidump"): part of what MapNG had in memory when it crashed, which shows where it failed. It can include things like file paths on your computer.
  • A report sent for a level (the Send report button in the levels list) also holds that level's export report: the text file MapNG writes into every level, with its settings, what was built, the checks and the export's log. It names the place, its coordinates and its streets all through, so this kind of report always goes with the location. The level's zip itself is not sent.
  • Never included: your name or any account, your files, the level itself, or anything else on your computer. Your internet address is used only for spam protection (at most 10 reports an hour), in memory, as a one-way hash, and is not stored with the report.
  • Where it goes: to mapng.com, into private Cloudflare R2 storage that only the developer can read. The developer gets an email saying a report arrived (a few an hour at most; the email holds the version, the error and what you wrote, not the log or the export report). Reports are not public, not shared, and not sold.
  • How it's used: only to find and fix the problem. You get a report ID (like MR-7F3KQ2) that you can mention on Discord or GitHub if you'd like an answer. The ID is the only link between a report and you, and only if you share it.
  • How long it's kept: until the problem is fixed, and no longer than a year.

Crashes are recorded by Electron's built-in crash reporter, which is set to keep crash snapshots on your computer and never upload them itself.

Problem reports from the website

The website can offer the same report when a Generate or an export fails. The rules are the same: nothing is sent unless you choose Send, and the window shows what is in it first.

  • What a website report can hold: the site's build, your browser and system in a few words (for example "Chrome 142 on Windows"), the memory and CPU threads your browser reports, the error message, the last lines the page wrote to its own log, the export settings, your control-panel settings as a session code, what you write, and the map's location and size. Untick the location and the report goes without the place, the session code and the export settings.
  • Never included: any name, email address or account (MapNG has none and asks for none), cookies, your GPXZ key, or anything from other tabs or your computer.
  • It goes to the same private storage as the desktop app's reports and is kept and used the same way. The code that builds a website report is short and commented: services/webReports.js.

If MapNG closes unexpectedly

A browser tab that runs out of memory takes your session with it. So that you don't lose your setup, MapNG leaves itself a note in your own browser's storage when a Generate or an export starts: which of the two it was, when, the build, and your settings as a session code. The note is removed when the job ends, and when you close or reload the page in the ordinary way.

  • If the note is still there the next time you open MapNG, the job never ended. MapNG then offers to restore your settings (you see what they are before anything is applied) and, if you want, to send a report.
  • The note never leaves your browser. No email address is asked for, nothing is sent to mapng.com, and it is shown once and then deleted. Clearing your browser's site data removes it too.
  • The code: services/sessionGuard.js.

Sending a config with a code

Under Share & save settings, Share my settings → Get a code gives you a short code like K7F-29Q, or a link like mapng.com/#K7F-29Q, to give someone. They enter it under Use someone's code.

  • What's stored: your control-panel settings (location, area, elevation source, and the export settings), the same settings Copy long code gives you. Never your keys or your own servers (GPXZ key, custom Overpass address).
  • Where: private Cloudflare R2 storage with no public access.
  • For how long: 24 hours, then the code stops working and the settings are deleted.
  • Who can see it: anyone who has the code. Nothing ties the code to you. Your internet address is used only for spam protection (at most 30 codes an hour), in memory, as a one-way hash, and is not stored.
  • Before anything changes, the person opening the code sees exactly what it would set and chooses Apply or Cancel.

Read the code

MapNG is open source, so none of this has to be taken on trust. The hotspot code is small:

  • services/exportHotspots.js: the grid and the rounding to a square
  • composables/useExportHotspots.js: the opt-in, the report, loading the overlay
  • worker/hotspots.js: the server: checks, spam limit, the table
  • services/hotspotLayer.js and services/heatLayer.js: drawing the glow and the dots

Questions, or something here that doesn't match the code? Open an issue on GitHub.
