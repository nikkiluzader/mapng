What the hotspot map is

The 2D map in MapNG has an optional Export hotspots overlay, in the Map Layers box. It shows the areas where people export BeamNG levels, as dots that get bigger and darker with more exports. The dots come only from people who chose to share. It helps everyone see where the community is building, and helps the developer decide where to improve MapNG next.

Sharing is off by default, on the website and in the desktop app. MapNG asks you once, after your first export, and the desktop app has an unticked box on its welcome screen. You can change your answer at any time with Share my exports (anonymous) in the Map Layers box on the map.

Exactly what one report looks like

When sharing is on and a level export finishes, MapNG sends one small message to https://mapng.com/api/hotspots. This is its entire content:

POST /api/hotspots
Content-Type: application/json

{ "y": 2397, "x": 1973, "platform": "web" }
FieldWhat it is
yThe row of the ~5 km grid square your export's centre falls in. The world is divided into 0.05° squares: 3,600 rows from south to north.
xThe column of that square: 7,200 columns from west to east.
platform"web" or "desktop": which version of MapNG made the export.

Your browser or the desktop app converts your export's location into that square before sending, so the exact coordinates never leave your computer. A square is about 5.5 km tall, and narrower further from the equator. Row 2397, column 1973 above is the square that contains part of St. Augustine, Florida: every export anywhere inside it sends the same three values.

That is the whole report: no level name, no settings, no map data, no account, no device or browser ID, no cookies.

Exactly what is stored

The server keeps one table with one row per grid square that has had at least one shared export. There is no other table, and nothing else is written anywhere.

ColumnTypeExampleMeaning
ywhole number2397Grid row of the square
xwhole number1973Grid column of the square
webwhole number14How many shared exports from the website fell in this square
desktopwhole number5How many shared exports from the desktop app fell in this square
last_daydate2026-11-04The day of the most recent one (a date, no time)

A report adds 1 to web or desktop for its square and sets last_day to today. Nothing records who sent it, and once added, a count cannot be traced back to anyone.

To turn a row into a place: the square's centre is at latitude -90 + (y + 0.5) × 0.05 and longitude -180 + (x + 0.5) × 0.05.

The whole pipeline, step by step

  1. An export finishesyour computer
    Only BeamNG level exports count. Nothing happens unless sharing is on.
  2. MapNG works out the grid squareyour computer
    The centre of your export is rounded down to its 0.05° square (services/exportHotspots.js). The exact point is discarded.
  3. One report is sentnetwork
    The three values above go to mapng.com/api/hotspots over HTTPS. If you're offline, the report is simply dropped; it is never queued or retried.
  4. MapNG's Cloudflare Worker checks itCloudflare
    The Worker (worker.js) refuses anything that isn't a valid square and platform. To stop one machine spamming the map, it allows at most 30 reports per hour per address (details below). Request logging is switched off for this Worker.
  5. The count goes up by oneCloudflare Durable Object
    A single Durable Object (hotspotsObject.js) holds the table in its built-in SQLite storage and adds 1 to that square's row.
  6. The overlay reads the totalsnetwork
    Anyone who turns on the overlay downloads the table from /api/hotspots. Cloudflare keeps a copy for up to 10 minutes so the database isn't asked on every page view.
  7. Dots are drawnyour computer
    Your browser merges nearby squares for the zoom level you're at and draws one dot per group (services/hotspotLayer.js).

The one thing kept in memory: spam protection

Without a limit, one person could fake thousands of exports. So for a short while the server remembers how many reports each address has sent this hour. It never writes this down. It works like this:

  • Your IP address is mixed with a fixed label and run through SHA-256, a one-way scramble. Only the first 8 bytes of the result are kept, in memory.
  • Next to it, a counter for the current hour. Over 30 reports in an hour, further reports are refused until the hour changes.
  • Entries from earlier hours are thrown away, and everything is lost whenever the server restarts. None of it is ever saved to storage or to a log.

Like every request to mapng.com, reports travel through Cloudflare's network, which runs the site. Cloudflare's own handling of traffic is covered by Cloudflare's privacy policy.

How the developer uses it

Only to look at the same totals everyone can see: which areas people build in. For example, MapNG hosts its own fast copy of OpenStreetMap data for a few regions, and the hotspot map shows which regions deserve that next. That's it.

Things MapNG will never do with it

  • Sell it
  • Share it with anyone (beyond the public totals on this page)
  • Use it for advertising
  • Track you, or link it to you
  • Combine it with any other data about you
  • Collect more without updating this page first

Your controls

  • Turn it on or off: the Map Layers box on the map → Share my exports (anonymous). Turning it off stops reports immediately.
  • Where your choice lives: on your own computer only, in local storage under the key mapng_share_exports (on or off). Clearing your browser's site data resets it, and MapNG will ask again.
  • Check it yourself: open your browser's developer tools, go to the Network tab, and export a level. With sharing on you'll see one POST to /api/hotspots with the three values; with it off, you'll see none.
  • Removing past counts: because nothing links a count to a person, individual exports can't be found and removed. If the hotspot feature is ever retired, the table will be deleted.

Everything else MapNG connects to

Read the code

MapNG is open source, so none of this has to be taken on trust. The hotspot code is small:

  • services/exportHotspots.js: the grid and the rounding to a square
  • composables/useExportHotspots.js: the opt-in, the report, loading the overlay
  • hotspotsObject.js: the server: checks, spam limit, the table
  • services/hotspotLayer.js: drawing the dots

Questions, or something here that doesn't match the code? Open an issue on GitHub.
