Security in MapNG

MapNG is a website and a desktop app. A program you install can do more than a web page, so here is every measure that limits what MapNG can do, how to check each one yourself, and what they do not cover.

You never have to install anything

The website does the same work as the desktop app, inside your browser's own sandbox. The desktop app exists for one reason: very large or very dense maps need more memory than a browser tab is allowed. If you would rather not run a program from the internet, use the website.

The website

  • Runs in your browser; it cannot touch your files except the ones you pick or save.
  • Your map is built on your own computer, not on a server.
  • Nothing to install, nothing to update.

The desktop app

  • Windows and Linux. The same pages as the website, in its own window.
  • Can use all of your computer's memory and write a level straight into your mods folder.
  • Held in by the measures below.

What holds the desktop app in

These apply to the Windows and Linux app from the version after 0.3.2 on, unless a card says otherwise.

Desktop

It connects only to a published list

Every address MapNG uses is on one list. The app refuses any other address before a request is made, in its window and in its export process. The one addition is your own Overpass server, if you set one.

See it: the list. Lift it yourself only by adding "allowUnlistedAddresses": true to the app's settings.json.

Desktop

It shows you what it contacted

Help > Network Activity lists every address the app has connected to since it started, how many requests it made, what each is for, and anything it refused.

Nothing in that window is sent anywhere or kept after you close the app.

Desktop

The window is sandboxed

The pages run in Chromium's sandbox with no access to the system. Only MapNG's own pages may ask the app to do something, and the window cannot be sent to another website.

A page from anywhere else gets no access to your files, even if one were somehow shown.

Desktop

It writes in three places only

Its own app folder, your Downloads folder, and the BeamNG mods folder you chose. Requests to write anywhere else are refused.

The folders, one by one: what the app writes.

Desktop

Updates must be signed by MapNG

The app takes an update only when the release's update file carries MapNG's signature, checked against a key built into the app. A changed file is refused. On Windows the new installer must also carry the same publisher's code signature.

Since 0.3.2. Update checks themselves are optional: Help > Check for Updates Automatically.

Desktop

Nothing runs behind your back

No background service, no start with Windows, no tray icon. When you close the window, running exports are stopped and the app is gone.

It downloads data only (elevation, maps, pictures), never programs. Its own signed update is the one exception.

How you know the download is the real one

Windows

A Windows code signature

The installer and the program are signed. The publisher is Nikki Luzader, MapNG's developer, whose identity Microsoft verified. The build that makes a release fails if a file comes out unsigned.

From the version after 0.3.2 on. Right-click the file > Properties > Digital Signatures.

Both

Built by a public workflow

Installers are built by GitHub Actions from a tagged commit of the public code. Every build's log is public, the build tools it uses are pinned to exact versions, and only the project's admin can create a release tag.

Both

Checksums and build provenance

Each release carries the SHA-256 of every download, and GitHub signs a statement of which commit and which build run produced each file. On Linux, where there is no code signature, these are the way to check a file.

The website and the server

Both

Only MapNG's own scripts run

The website and the app send a content security policy: scripts come from MapNG itself and nothing injected is allowed to run. Nothing is loaded from an advertising or tracking service, because there is none.

Server

A small, fenced server

mapng.com mostly hands out files. Its few services (map data, relays for elevation and place search, send codes, opt-in stats and reports) accept only the request shapes they need and answer with strict security headers; MapNG's own services never set a cookie.

Server

Limits against abuse

Each sender is limited per minute, and each service has a daily total for everyone together, so one script cannot flood the server or use MapNG to hammer the data sources it relays.

Server

No secrets in the code

Keys and tokens live in the hosting provider's secret store. The repository, its history and the built files were checked for them in the November 2026 review.

Your data and your keys

  • No account. No sign-in, no email, no device ID.
  • Sharing is opt-in. Export hotspots, settings stats and problem reports are sent only if you turn them on or press Send. A report shows you everything in it first.
  • Your keys stay with you. A GPXZ key or an Overpass address with a key is kept on your computer, removed from an export's job files when the export ends, and hidden in logs and reports. One thing to know: a request to GPXZ goes by way of mapng.com, which hands it on with your key and does not store or log the key.
  • Shared settings are checked. A config you paste or open by code is cleaned first, and the dialog names any risky setting before you accept it.

Check it yourself

  1. See the Windows signature. Right-click the installer, choose Properties, then Digital Signatures. Or in PowerShell: 
    Get-AuthenticodeSignature .\MapNG-Setup-x.y.z.exe
    The status is Valid and the signer is Nikki Luzader.
  2. Compare the checksum. Download SHA256SUMS-win32.txt or SHA256SUMS-linux.txt from the same release, then: 
    Get-FileHash .\MapNG-Setup-x.y.z.exe -Algorithm SHA256     # Windows
sha256sum MapNG-x.y.z-x86_64.AppImage                       # Linux
  3. Check where it was built. With GitHub's command line tool: 
    gh attestation verify MapNG-Setup-x.y.z.exe --repo nikkiluzader/mapng
    It names the commit and the build run that produced the file.
  4. Watch what it connects to. In the app, Help > Network Activity. Or watch the network with your own tools and compare with the list.
  5. Read the code. The pieces named on this page: the address list, the guard, the update signature, the app's main process, the server.

What this does not cover

Security pages that only list strengths are not worth much. These are the limits.

  • No outside audit. The project reviewed its own server, app and website in November 2026 and fixed what it found. Nobody independent has audited it.
  • An installed program is still an installed program. The measures above limit what MapNG's own code does. They cannot make a program as contained as a web page. If that matters to you, use the website.
  • Windows may still warn. SmartScreen judges a new installer by how many people have downloaded it, so a fresh release can show a warning even though it is signed. The publisher's name in that warning is what to check.
  • Some list entries are broad. A few addresses on the list stand for a whole family (for example the storage addresses that USGS and GitHub hand out), because those services choose the exact address themselves.
  • The website is not fenced the same way. A browser page cannot be limited to a list of addresses by MapNG; there the list is what the code contains, checked by a test.
  • Linux has no code signature. The AppImage is checked by its checksum and build provenance instead.
  • Older versions. Version 0.3.2 and older are not signed for Windows and do not refuse unlisted addresses.
  • You are trusting the build and hosting services. GitHub builds the app, Microsoft's signing service signs it, and Cloudflare serves the site. MapNG can show you what was built from which code; it cannot vouch for those companies' own systems.
  • The maps come from public data. MapNG reads elevation and map data from other services. It treats what it downloads as data, never as code, but it cannot promise those services are always available or correct.

Report a problem

Found a security problem? Please report it privately, so it can be fixed before it is public: open a private report on GitHub. Say what you found, how to reproduce it and which version or page it concerns. For anything else, open an issue.

The same information for developers is in the repository's SECURITY.md.
